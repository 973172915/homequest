## 阶段一：数据体检

| 项 | 内容 |
|---|---|
| 输入 | `data/sh_data.csv`，18339 行 × 16 列 |
| 技术 | **pandas 3.1.1**、正则、分位数统计 |
| 产出 | `artifacts/reports/profile_report.txt` |
| 代码 | `scripts/profile_data.py` |

**关键发现（直接改变了建模方案）**：

1. `unit_price` 完全由 `total_price × 10000 ÷ square` 推导而来（误差 < 0.2%）→ 它是派生列，不是独立信息，**不需要做单价一致性清洗**
2. `id` 范围 0~20825 但只有 18339 个 → **这是抽样后的子集**，写报告时必须声明
3. 8 个区县里有 2 个是县级市（寿光、青州），价格体系与市区不同 → 必须分区县评估
4. 无缺失、无非数值、户型/楼层/梯户比 100% 可解析 → 清洗不会卡住

## 阶段二：清洗与特征工程

| 项 | 内容 |
|---|---|
| 输入 | 原始 CSV |
| 技术 | **pandas** 向量化字符串操作 + 正则 |
| 产出 | `artifacts/processed/clean.parquet`（18332 条） |
| 代码 | `housing/ingest/clean.py` |

**四个中文串字段的解析规则**：

| 字段 | 原始形态 | 解析成 | 正则 |
|---|---|---|---|
| `size` | `3室2厅1厨1卫` | rooms / halls / baths | `(\d+)室(\d+)厅(\d+)厨(\d+)卫` |
| `floor` | `中楼层 (共11层)` | floor_level + total_floors + floor_ratio | `(低\|中\|高)楼层.*?共(\d+)层` |
| `elevatorNum` | `一梯两户` / `八梯十四户` | elevators / units_per_floor | 中文数字转换 |
| `direction` | `南 北` | has_south/north/east/west + south_north | 多热编码 |

**额外派生**：面积段、是否顶楼、卖点关键词（车位/储藏/急售/满二/出税）。

**异常处理**：单价 < 2000 或 > 50000 的 7 条剔除，但保留 542㎡ 的真实豪宅——**按业务阈值删，不按分位数删**。

## 阶段三：房源文档化（RAG 的语料构造）

| 项 | 内容 |
|---|---|
| 输入 | `clean.parquet` |
| 技术 | **langchain_core.documents.Document** + Python 模板字符串 |
| 产出 | 18332 个 Document |
| 代码 | `housing/ingest/build_docs.py` |

**核心决策：一房一文档，不切块。**

每套房序列化成约 100 字：

```
【房源 10023】潍坊市奎文区 · 新华路北 · 东方天韵
3室2厅2卫 / 135.5㎡ / 中楼层(共18层) / 南北通透 / 精装 / 有电梯（2梯3户）
总价 127 万，单价 9374 元/㎡
卖点：人民医院近，楼层好，H 户型，配套齐全
```

metadata 里挂结构化字段（面积、价格、区县、户型、装修、电梯），供检索时做硬过滤。

**为什么不切**：一条房源总共 100 字，本身就是完整语义单元。按 `chunk_size=500` 切，会把「小区名」和「价格」拆散，还会让两套房混进同一个向量。

## 阶段四：知识库切块

| 项 | 内容 |
|---|---|
| 输入 | `data/kb/*.md`（5 篇政策语料） |
| 技术 | **langchain_text_splitters.RecursiveCharacterTextSplitter** |
| 产出 | 10 个文本块 |
| 代码 | `housing/ingest/build_kb.py` |

参数：`chunk_size=400 / overlap=60`，分隔符按中文标点降级：

```python
["\n\n", "\n", "。", "；", "！", "？", "，", " ", ""]
```

**这就是阶段三和阶段四的对比**：结构化记录不切，自由长文才切。多数 RAG 教程会教你对所有文本无差别切块，那是错的。

## 阶段五：向量化与索引

| 项 | 内容 |
|---|---|
| 技术① | **sentence-transformers 6.2.0** + **BAAI/bge-small-zh-v1.5**（100 MB，CPU 可跑） |
| 技术② | **FAISS 1.15.1**（`IndexFlatIP` 暴力内积检索） |
| 技术③ | **rank-bm25 0.2.2** + 自研中文分词器 |
| 产出 | `artifacts/index/faiss_listings`、`faiss_knowledge` |
| 代码 | `housing/search/embeddings.py`、`faiss_store.py`、`tokenizer.py` |

**三个工程决策**：

1. **query 侧加 bge 指令前缀** `为这个句子生成表示以用于检索相关文章：`，文档侧不加 —— 官方技巧，召回提升 2~3 个点
2. **FAISS 自己写序列化**：FAISS 的 C++ 层用 ANSI `fopen` 打开路径，项目路径含中文会报错，改成 `faiss.serialize_index()` 取字节 + Python `open` 写盘
3. **不用 jieba**：它只发布源码包，安装要本地编译 wheel。改用**字符二元组**（`东方天韵` → 东/方/天/韵/东方/方天/天韵），在「小区名精确匹配」上召回更好，还少一个依赖

## 阶段六：混合检索

| 项 | 内容 |
|---|---|
| 技术 | **EnsembleRetriever**（langchain-classic）+ **MMR** + 自写硬过滤 + 自写重排 |
| 代码 | `housing/search/retriever.py` |

**三路各司其职**：

| 层 | 解决什么 | 权重/k |
|---|---|---|
| BM25（字符二元组） | 「东方天韵」这类精确小区名 | 0.3 |
| 向量 + MMR | 「南北通透、采光好」的语义相似 | 0.7 |
| 硬过滤 + 重排 | 预算、面积、户型、装修**必须满足** | 规则 |

流程：先召回 200 条 → 去重 → 按条件硬过滤 → 重排 → 取 Top10。

**为什么要硬过滤**：向量相似度不懂「80 万以内」这种数值大小。让模型理解价格约束是不可靠的，必须用规则兜住。

## 阶段七：意图解析

| 项 | 内容 |
|---|---|
| 技术 | 纯规则：正则 + 别名字典 + 最长匹配 |
| 产出 | `SearchFilters` 数据类 |
| 代码 | `housing/search/retriever.py::parse_query` |

能解析 8 个维度：区县（含简称「高新区」）、商圈、小区名、价格、面积、户型、装修、电梯。

**为什么用规则不用 LLM**：

- 确定性：同样的输入永远同样的输出，可测试
- 零成本、零延迟（< 1 ms）
- 评测可以逐字段比对，能做到 100%

**踩过的两个坑**（都写进了测试）：

- 「高新实验」（学校名）被「高新」这个区县简称误吞 → 先识别商圈/小区，从文本剔除后再识别区县
- `nearby` 字段里 `寿光市`/`青州市` 与区县同名，把区县条件吃掉 → 加区县同名判别

## 阶段八：问题路由

| 项 | 内容 |
|---|---|
| 技术 | 关键词 + 条件判空 |
| 代码 | `housing/advisor/chain.py::is_policy_query` |

规则：命中税费/贷款/过户等关键词，**且**没提区县/小区/商圈/户型/面积/装修 → 判定为政策问题，走知识库；否则走房源库。

「只出现价格不算找房」——「100 万的房子契税多少」问的是税费，不是房源。

## 阶段九：生成层

| 项 | 内容 |
|---|---|
| 技术① | **LangChain LCEL**（`ChatPromptTemplate \| ChatOpenAI \| StrOutputParser`） |
| 技术② | **DeepSeek `deepseek-flash`**（OpenAI 兼容协议，1M 上下文） |
| 技术③ | **SSE** 流式输出 |
| 代码 | `housing/advisor/prompts.py`、`chain.py`、`llm.py` |

**三条硬约束（防幻觉）**：

1. 只能依据【房源】/【资料】里的信息，禁止编造
2. 每条推荐必须带 `[房源编号]`，前端可回溯
3. 返回 `{answer, sources}`，而不只是文本

**成本与延迟优化**：

- `reasoning_effort="none"` 关闭思考模式：首字 38.9s → 15.5s
- 打开 `streaming=True`：首字 2.7s
- 无 Key 时 `get_llm()` 返回 `None`，自动降级为「检索 + 模板摘要」

## 阶段十：估价模型

| 项 | 内容 |
|---|---|
| 技术 | **LightGBM 4.7.0**（GBDT）+ **scikit-learn 1.9.1**（切分、指标） |
| 目标 | `log(unit_price)`，L2 损失 ≈ 最小化相对误差 |
| 特征 | 12 个数值 + 4 个类别（区县/商圈/小区/楼型） |
| 产出 | `artifacts/models/price_model.txt` + `eval/results/model_eval.md` |
| 代码 | `housing/estimate/model.py`、`scripts/train_model.py` |

**两个关键设计**：

1. **估单价不估总价**：总价 = 单价 × 面积，面积做特征就够，避免模型浪费容量学乘法
2. **双切分评估**：随机切分 10.34%（同小区泄漏，偏乐观）+ 按小区分组切分 14.72%（真实场景）

**解释性**：用 `booster.predict(X, pred_contrib=True)`，等价 SHAP 但不需要 `shap` 依赖。满足「基准值 + 各特征贡献 = 预测值」。
